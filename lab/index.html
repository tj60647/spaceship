What makes this a decision model?

A text-generation model writes a continuation. A decision model answers a specific question about supplied information in a structured form: a score, label, or probability. The application decides what to do with that answer.

For example: measure relevance to highlight a passage, check a writing instruction to flag a draft for review, or suggest an inbox label. A score is a judgment, not a fact. Test ambiguous cases before relying on it.

Where does Spaceship use the model?

This is Chuanqi Sun’s original relevance implementation, pinned to the version this adaptation started from. The teaching passage is new; the question and scale come from this code.

  1. Choose Gemini Decision 1 and a four-level scale

    live-relevance.ts · model and scale ↗ 

    const MODEL = "gemini-decision-1"
const LEVELS = [
  "Not relevant",
  "Weak: shares the setting or a passing detail",
  "Moderate: bears on what the tip is about",
  "Strong: the tip is about it, or turns on it",
]

  2. Ask a question about each keyword

    live-relevance.ts · question construction ↗ 

        leads.map((lead, i): [string, Question] => [
      keyOf(i),
      { type: "score", instructions: `How relevant is keyword [${i + 1}] "${lead.keyword}" to the TIP?`, criteria: LEVELS },
    ]),
  )
  const { answers } = await createDecisions(apiKey, { model: MODEL, input, questions }, signal)

  3. Call the model, then use its score

    live-relevance.ts · the actual model call ↗ 

      const { answers } = await createDecisions(apiKey, { model: MODEL, input, questions }, signal)

  for (const index of leads.keys()) {
    const answer = answers[keyOf(index)]
    if (answer?.type === "score") yield { index, relevance: answer.score / (LEVELS.length - 1) }
  }

    A score of 3 becomes relevance 1.0; a score of 1.5 becomes 0.5. The app uses this normalized value in its attention-box UI.

What changed in this hosted adaptation?

The original sends requests directly to Google with a browser-held key. This version keeps the scoring logic but routes requests through src/llm/decisions.ts → api/decide.js → server/inference.js to OpenRouter, with server-held credentials and access checks.

The lab’s teaching presets live in src/lab/examples.ts. Editing them does not change the flight deck’s questions.
